# Design Decisions

Short log of choices that shape the toolkit, newest last. Each entry: what, why, alternative rejected.

## 2026-09-27 -- One repo, hub + per-tool pages
Every tool lives in this repo behind a hub page rather than in its own repo. Shared validation helpers, page shell and CI are written once, and the portfolio reads as one body of work. Rejected: one repo per tool (duplicated infrastructure, ten thin repos). Split by family later only if a tool outgrows this repo.

## 2026-09-27 -- Python core + Pyodide browser pages
Logic is a tested pure-Python library; each browser page is a thin layer that runs the same code via Pyodide, so tests cover what users run. Same pattern as wacc-toolkit. Rejected: reimplementing logic in JS (two copies drift).

## 2026-09-27 -- Manifest-generated fetch list, `.nojekyll`
Carried over from wacc-toolkit's live-site bugs: a hand-maintained module fetch list broke the browser page, and Jekyll silently 404s underscore-prefixed files such as `__init__.py`. The manifest is generated and guarded by `tests/test_manifest.py`.

## 2026-09-27 -- CI runs pytest on every push
Visible test status is part of the portfolio signal. Pages is branch-based, so no deploy workflow is needed.

## 2026-10-02 -- Validation policy: primary-page sources, errors documented not reproduced (logged late; adopted from tool 2.2 on)
Every tool is validated against a source read at its primary page (the fetch tool returns a model summary, so numbers are recomputed). When a source is wrong, the error is documented in `docs/validation.md` and the tool does not reproduce it (safety-stock textbook ROP, DFMA extrusion weight step). Where no authoritative source exists, the tool says so on its page (should-cost). Rejected: citing search-engine summaries, or matching a published number that is itself wrong.

## 2026-10-02 -- Make-vs-buy shipped linear first (logged late; decided building tool 2.2)
v1 uses linear cost per unit and one fixed cost. Step-fixed costs and price breaks are extension 2.2b with its own spec. Rejected: building every cost shape at once, which would have delayed the first verified tool and widened the validation surface.

## 2026-10-02 -- No unverifiable citations (logged late; decided building tool 1.1)
COPQ carries no numeric source citation because none was found; the page and `docs/validation.md` say it is validated by definitions (ASQ prevention-appraisal-failure) and hand-computed cases only. Rejected: attaching a plausible-looking reference to make the tool look more authoritative.

## 2026-10-02 -- Sample-size v1: means only, exact t power, no false-positive cost term (logged late; decided building tool 2.1)
t tests (one-sample/paired, two-sample equal n) with exact noncentral-t power, and a cost-minimizing n. No cost for a false positive, because at a fixed alpha it is a constant that cannot change the optimal n. Proportions (2.1b) and DOE planning (2.1c) are deferred. Rejected: the normal approximation (understates n at small samples) and a made-up alpha cost.

## 2026-10-02 -- Should-cost is a generic process chain with a hand-off flag, reported as a bounding range (logged late; decided building tool 3.6)
Extruders, laminators and pouch formers sit at different points in the value stream and may or may not be one company, so the engine is an ordered list of steps with a per-step separate-company flag (margin stacking), not a film-specific model. Output is a low/base/high range (an outer bound, not a confidence interval) because rough estimation is the honest standard. Rejected: a film-only tool and a single point estimate.

## 2026-10-02 -- User-entered prices only, no shipped market data (logged late; decided building tool 3.6)
Resin and commodity indices are paywalled and go stale, and shipped prices would invite being read as current quotes. Every price and rate is a user input. Rejected: bundling a snapshot price table.

## 2026-10-02 -- Simulation helpers: stdlib only, independent inputs, shared incomplete beta (tool 0.6)
`opstoolkit/simulation.py` uses only the standard library (no NumPy in Pyodide), draws inputs independently (correlation is a possible 0.6b and the docs say so), samples truncated normals by inverse cdf instead of rejection (no failure mode), and shares one incomplete-beta implementation with the sample-size tool. Validated against SciPy reference values generated by an independent script, with a mutation check. Rejected: NumPy dependency (heavier page load), Latin hypercube in v1.
