Plus algebraic checks and a hand-computed TCO case (`docs/specs/02-make-vs-buy.md` §7) from a standalone script. | `tests/test_make_vs_buy.py` |
| Safety-Stock & Service-Level Optimizer | **Published examples, verified at the source 2026-09-28:** eCampusOntario *Fundamentals of Operations Management* §8.5 (three EOQ examples: Apple Canada, BestBuy, Modern Furniture) and §8.7 (kiosk safety stock, printed SS 5.12 vs. exact-z 5.126). **Erratum in the source, not reproduced:** the kiosk example prints ROP = 4 + 5 = 9, using the standard deviation where the page's own formula needs the mean lead-time demand (20), so the correct ROP is about 25. The optimal-service-level extension is not in that book: validated by brute-force grid search and the loss function by numerical integration and table values. Plus a hand-computed case from a standalone script. | `tests/test_safety_stock.py` |
| Sample-Size & Cost-of-Testing Planner | **Published examples, reproduced independently 2026-10-01:** the Minitab *Power and Sample Size for 2-Sample t* example (difference 5, SD 10, power 0.90 -> n = 86 per group, actual power 0.903230) and the NIST/SEMATECH e-Handbook §7.2.2.2 one-sample example (one-sided, alpha .05, beta .10, delta = sigma: normal formula 8.567 -> 9, t-iteration 10.6 -> 11; exact power also gives 11). The stdlib noncentral-t and t-quantile machinery is checked against SciPy reference values (SciPy generated the constants once; it is not a library dependency). **Open item:** the NIST sample-size *table* is not asserted: its values match the normal formula to within 1 but sit far below exact-t at larger effects, and its own method has not been read at the source page. The cost-minimizing n is validated by brute-force scan over n; the §7 case is checked against a standalone SciPy script. | `tests/test_sample_size.py` |
| Process-Chain Should-Cost Builder | **Structural and arithmetic validation only; stated on the page. No authoritative published end-to-end should-cost with a known quoted price was found.** Published examples are vendor web pages, read at the primary page 2026-10-01 with arithmetic recomputed: the BN Pack film-yield example (2,500 m roll, 4 lanes, 0.20 m repeat: 50,000 theoretical, 47,000 good at 94%, $4,230 roll -> $0.09, +$0.007 -> $0.097; 3-lane variant 37,500) reproduces. **Erratum in the DFMA *Plastic Extrusion Cost Estimating* page, not reproduced:** its weight step prints "0.75 in2 x 12 in/ft x 1.4 g/cc / 16.387 = 0.77 lb/ft", a unit error; the correct value is 0.75 x 12 x 16.387 x 1.4 / 453.59 = 0.455 lb/ft (material $0.296/ft, not $0.50; total about $0.407/ft, not $0.611). The Pro Pac square-inch page states the yield rule as thickness x density / 27.68 (lb per 1,000 in2), the reciprocal of this tool's identity 27,680 / (mils x SG); a search-engine summary of that page had garbled it, which is why it was read directly. Also: algebraic and monotonicity checks (single-company closed form, hand-offs only add cost, waste line equals the difference of two runs, kg/hr and m/min steps agree, low <= base <= high) and hand-computed reference cases A, B, C and the range from a standalone script (`docs/specs/05-flex-should-cost.md` §7). | `tests/test_should_cost.py` |
| Shared Simulation Helpers (0.6, library only) | **Checked against independent SciPy/NumPy references, 2026-10-02** (`scripts/simulation_reference_values.py`; SciPy is a reference tool only, never a library dependency): analytic mean, variance, P10/P50/P90 and cdf for uniform, triangular, modified PERT, normal, truncated normal (three bounds cases) and lognormal; the lognormal arithmetic-mean/sd conversion; and NumPy's default percentile on ties, unsorted and tiny inputs. Sampling is checked at 200,000 draws: moments within 4 standard errors (SE of the variance from the sample's own fourth moment), percentiles within 4 SE of a quantile, passing under six different seeds as well as the committed one. Also: cdf/ppf round trip, determinism, input independence (|r| < 4/sqrt(n)), sum-of-normals composition by hand, and a mutation check (11 deliberate bugs, all caught). **The spec's own worked example was wrong** (Triangular(10,12,20) variance printed 6.2222 and P50 13.162; correct 4.6667 and 13.675); the independent script caught it before any code existed, and the spec is corrected in place. **Stated limits:** inputs are independent (no correlation); the distribution shapes are modelling choices, so results are scenario ranges, not forecasts. Under Pyodide the results are bit-identical to CPython for the same seed (10,000 draws 0.06 s; the 200,000 cap 0.9 s). | `tests/test_simulation.py` |
